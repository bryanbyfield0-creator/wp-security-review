Who I am

I'm Bryan Byfield, a web developer in San Bernardino, California. I've been building and maintaining websites since 2015, mostly on WordPress. I test everything on a real install before I tell anyone it works, and that includes security findings: if I write it in a report, I have reproduced it.

This service is for people who write plugins and themes. If you ship code to other people's sites, a second pair of eyes before a release or before a directory submission is cheap compared with a vulnerability report after the fact.

What I check

  • Capabilities and nonces. Every AJAX action, admin-post handler and form: who can call it, and can another site trigger it for a logged-in user.
  • SQL injection. Every query, whether it goes through $wpdb->prepare(), and how LIKE values and IN() lists are built.
  • Cross-site scripting. Stored, reflected and shortcode-attribute output: is data escaped on the way out, in the right context.
  • REST API routes. Every register_rest_route() and its permission_callback, plus how request data is validated.
  • File handling. Uploads, downloads, exports and any path built from user input: file type checks, path traversal, where files land.
  • The basics around them. Input sanitizing, direct file access, options and settings pages, and anything that handles user roles.

What you get back is a findings report: a summary table, then one entry per issue with the file and line, who can trigger it, how I reproduced it, a rating, and a suggested fix you can paste in. Here is a full sample.

How it works

  1. Email me a zip of the plugin or theme, or a link to a private repository.
  2. I reply with the line count, the tier and the delivery date. You say yes or no.
  3. I review the code and test each finding on a local WordPress install, using the roles that matter: logged-out visitor, subscriber, contributor, administrator.
  4. You get the report as a PDF and Markdown file.
  5. After you have it, I send a PayPal invoice for the tier price.

Questions

Will you publish what you find?

No. The report is private to you. I don't disclose anything publicly and I don't submit what I find about your code anywhere else.

Do you test on my live site?

Never. I test only on a local install I set up myself, with your code.

What happens to my code?

I keep it confidential and delete my copy 30 days after I send the report, or sooner if you ask.

Does a clean report mean my plugin is secure?

No. It's a point-in-time review of the version you send me, not a certification or a guarantee. The report states the scope, and I'll say plainly if something is outside it.

Do you fix the problems too?

The review includes a suggested fix for every finding. Applying them is up to you, and I'll recheck your changes once, as described above. If you'd like me to make the fixes, email me and I'll quote it separately.

Can I see what a report looks like first?

Yes: the sample report is a review of a demo plugin I wrote myself, with deliberately planted bugs, so no real plugin or person is involved. The demo plugin, the fixed version and the check script are public.
